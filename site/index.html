Inspect your saved records locally

Select one exported decision record to inspect its complete state and saved answer. Select a second to compare inputs first, then recorded values. Files and names stay in this page session. They are not uploaded, put in links or saved in browser storage. Reload or clear them to release the imported state.

This viewer checks the supported representation and input consistency, then derives actions permitted by the saved modeled state. It does not recompute an answer, establish external table buttons or authenticate the record's origin. To recalculate through your installed engine, use bj-advise --replay PATH --json. Package versions are supplied labels. Schemas 1 and 2 retain the independent-hand and greedy shared-budget split approximation, with no general error bound. Schema 3 explicitly declares a bounded common-shoe model for two split hands. Schema 4 declares bounded post-peek late surrender for one original initial hand, with supplied depleted counts and current permission. Inspect each family's coverage before comparing recorded values.

Export a small record after setup
bj-advise T,4 T --unseen 2,3,7,8,9,T --json

Add --no-double or --no-split to exclude that current choice without changing continuation rules. Defaults keep version 1 records; a disabled choice produces version 2 with stored controls. The viewer distinguishes these declarations from implicit defaults.

Save the command's JSON output as a UTF-8 file using your shell or editor. The viewer accepts schema versions 1, 2, 3 and 4, at most 65,536 UTF-8 bytes, container depth eight and integer tokens up to 4,300 decimal digits. Those are browser representation limits, not engine work or memory limits. Integer counts remain exact. Raw answer numbers are interpreted as finite binary floats without display rounding.

Read the saved-record guide for the installed exporter and replay journey. The common-shoe guide supplies its explicit bounded request. The late-surrender guide supplies the separate initial-hand request, compute and replay commands. Its R permission and half-wager settlement do not extend the older models.

The transferable work is numerical software and verification. A correct result inside this rule model does not establish a model for financial risk or another real-world decision.

What this shows

These saved examples use six decks, a dealer who stands on soft 17, a completed peek without blackjack and no surrender. Values are expected net return per original wager, not win probabilities. Both hands have negative expected return. Split valuation elsewhere in the project is approximate.
